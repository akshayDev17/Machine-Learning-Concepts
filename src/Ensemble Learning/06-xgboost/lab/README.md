# XGBoost Lab — run it, look at it, understand it

This folder is the hands-on half of the XGBoost notes. The theory is in [`../README.md`](../README.md); every claim
made there is shown here with code, numbers and plots — once with the `xgboost` library, and once rebuilt from
scratch in NumPy and checked against the library.

## What is where

| File | What it is |
|---|---|
| [`xgboost_lab.ipynb`](xgboost_lab.ipynb) | **The library lab.** 16 labs in 3 parts (how it works, why it is useful, where it fails), using `xgboost` and scikit-learn. Already executed: you can read every result on GitHub without installing anything. |
| [`xgboost_from_scratch.ipynb`](xgboost_from_scratch.ipynb) | **XGBoost rebuilt in NumPy**, one README step per section, with "implementation hurdle" boxes; ends with a comparison against `xgboost(tree_method="exact")` on both datasets (predictions agree exactly). |
| `data/good_fit.csv` | 8 000 rows × 8 features + `y`: non-linear target with interactions and **informative missing values** (`nan`). Generated by both notebooks (same seed, same file). |
| `data/bad_fit.csv` | 150 rows × 400 features + `y`: a sparse **linear** target (10 features matter) — where XGBoost is the wrong tool. |
| [`requirements.txt`](requirements.txt) | The Python packages the notebooks need. |
| `README.md` | This guide. |

All data is generated inside the notebooks (no internet needed); all results (printed numbers and plots) appear
directly **under the code cell that produced them**.

## How to run it

From the repository root:

```bash
python3 -m venv .venv
```

```bash
source .venv/bin/activate
```

```bash
pip install -r "src/Ensemble Learning/06-xgboost/lab/requirements.txt"
```

**macOS only:** the `xgboost` package needs the OpenMP runtime. If `import xgboost` fails with a message about
`libomp.dylib`, install it with [Homebrew](https://brew.sh):

```bash
brew install libomp
```

Then, in **VS Code** (with the Python and Jupyter extensions installed):

1. Open `src/Ensemble Learning/06-xgboost/lab/xgboost_lab.ipynb` (or `xgboost_from_scratch.ipynb`).
2. Click **Select Kernel** (top right) → **Python Environments** → the `.venv` you just created.
3. Run cells one by one with **Shift + Enter**, or everything with **Run All**. Measured on an Apple-silicon
   MacBook: `xgboost_lab.ipynb` about **1 minute**, `xgboost_from_scratch.ipynb` about **35 seconds** (the
   from-scratch booster is plain Python + NumPy, so it is 10–20× slower than the library — on purpose, for
   readability).

* **Always run the first code cell (imports) first.** After that, run in order; a lab only reuses variables from
  earlier cells, so top-to-bottom always works. Both notebooks write the same two CSVs into `data/`.
* Prefer the browser instead of VS Code? `pip install jupyterlab`, then
  `jupyter lab "src/Ensemble Learning/06-xgboost/lab/xgboost_lab.ipynb"`.
* Just want to read? Open the notebooks on GitHub; the outputs are saved in them.

## How each lab is laid out

Every lab has the same four parts, so you always know where to look:

1. **Heading + Goal** (markdown) — which question from the README this lab answers.
2. **Code cell(s)** — short, commented, nothing hidden in helper files. Lines marked `# <- try changing this` are
   good knobs to experiment with.
3. **Output** — printed numbers and/or plots directly underneath.
4. **"How to read this" box** (a quoted markdown block) — what you should notice in the output and what it proves.
   Try to guess before you read it.

The from-scratch notebook replaces the "Goal" with the README equation being implemented, ends each section with a
**check** (an `assert` against the README's numbers or against `xgboost`), and adds **Implementation hurdle** boxes.
Both notebooks end with a **Summary** table.

## How to interpret the results — quick guide

* **RMSE** (root mean squared error) — typical size of a prediction error, in the units of y. Lower is better.
  Compare it with the standard deviation of y (what you get by always predicting the mean).
* **R²** — share of the variance of y explained: 1 = perfect, 0 = no better than predicting the mean, < 0 = worse.
* **Log-loss / AUC** (classification) — log-loss: lower is better; AUC: probability that a random positive gets a
  higher score than a random negative (0.5 = coin flip, 1 = perfect).
* **Validation vs test** — validation scores are used to *choose* things (number of trees, settings); the test score
  is computed once at the end and is the honest estimate.
* **Tree dumps** — `split_condition` is a threshold with "yes = left = `x < split_condition`"; `missing` names the
  child that receives NaN; `gain` is xgboost's gain **without** the ½ (twice the README's); `leaf` is η × w*.
* **`max|Δpred|`** (from-scratch notebook) — largest difference between our prediction and xgboost's on any test row;
  0 means bit-for-bit identical.

If your numbers differ in the third decimal place from the saved outputs, that is due to library versions and is
fine; timings differ from machine to machine. If a lab errors, re-run the imports cell and the labs above it — most
errors mean a variable from an earlier lab is missing.
