# Voting Lab — run it, look at it, understand it

This folder is the hands-on half of the voting notes. The theory is in [`../README.md`](../README.md); every claim made
there is shown here with code, numbers and plots — once with scikit-learn, once rebuilt from scratch in NumPy.

## What is where

| File | What it is |
|---|---|
| [`voting_lab.ipynb`](voting_lab.ipynb) | **The library lab.** 14 labs in 3 parts, using scikit-learn's `VotingClassifier`, `VotingRegressor` and `StackingClassifier`. Already executed: you can read every result on GitHub without installing anything. |
| [`voting_from_scratch.ipynb`](voting_from_scratch.ipynb) | **The from-scratch notebook.** The vote rules *and* the three members (logistic regression, Gaussian naive Bayes, k-NN) in NumPy, each compared with scikit-learn on the same data, plus the implementation hurdles (ties, column alignment, overflow, probability scales, out-of-fold stacking). Already executed. |
| [`data/good_fit.csv`](data/good_fit.csv) | The "good fit" map (1328 rows, columns `x1,x2,y`): three members that fail in three different places. Generated by `make_good_fit()` in the library lab. |
| [`data/bad_fit.csv`](data/bad_fit.csv) | The "bad fit" XOR (1050 rows, `x1,x2,y`): only k-NN can solve it, the other two fail together. Generated by `make_bad_fit()`. |
| [`requirements.txt`](requirements.txt) | The Python packages the notebooks need. |
| `README.md` | This guide. |

All data is generated inside the library notebook (and saved to `data/`) or comes from scikit-learn's built-in
generators (no internet needed). The from-scratch notebook reads the two CSV files, so run the library notebook first
if you delete them. All results (printed numbers and plots) appear directly **under the code cell that produced them**.

## How to run it

From the repository root:

```bash
python3 -m venv .venv
```

```bash
source .venv/bin/activate
```

```bash
pip install -r "src/Ensemble Learning/01-voting/lab/requirements.txt"
```

Then, in **VS Code** (with the Python and Jupyter extensions installed):

1. Open `src/Ensemble Learning/01-voting/lab/voting_lab.ipynb` (then `voting_from_scratch.ipynb`).
2. Click **Select Kernel** (top right) → **Python Environments** → the `.venv` you just created.
3. Run cells one by one with **Shift + Enter**, or everything with **Run All**. Measured on an M4 MacBook Pro:
   `voting_lab.ipynb` about **7 seconds**, `voting_from_scratch.ipynb` about **3 seconds**.

* **Always run the first code cell (imports) first.** After that, labs can be run in order; a lab only reuses
  variables from earlier cells, so top-to-bottom always works.
* Prefer the browser instead of VS Code? `pip install jupyterlab`, then
  `jupyter lab "src/Ensemble Learning/01-voting/lab/voting_lab.ipynb"`.
* Just want to read? Open the notebooks on GitHub; the outputs are saved in them.

## How each lab is laid out

Every lab has the same four parts, so you always know where to look:

1. **Heading + Goal** (markdown) — which question from the README this lab answers.
2. **Code cell(s)** — short, commented, nothing hidden in helper files (the only helpers, `make_members` and
   `plot_regions`, are in the imports cell). Lines marked `# <- try changing this` are good knobs to experiment with.
3. **Output** — printed numbers and/or plots directly underneath. In the decision-region plots the background colour
   is what the model predicts there (light blue = class 0, light red = class 1), dots are test points, and a black ×
   marks a test point the model gets wrong.
4. **"How to read this" box** (a quoted markdown block) — what you should notice in the output and what it proves.
   Try to guess before you read it.

The from-scratch notebook follows the theory step by step instead: a short statement of the step (with the README §),
the NumPy function, then a check against the README's numbers or against scikit-learn. **Implementation hurdle** boxes
mark the places where writing it yourself goes wrong, each with a demonstration.

Both notebooks end with a **Summary** table listing every lab / section and what it showed.

## How to interpret the results — quick guide

* **Accuracy** — share of test points classified correctly (0.5 = coin flip for two balanced classes). Every
  comparison uses the same 70 / 30 split (`random_state=0`, stratified) that the model never trained on.
* **Hard vs soft vote** — hard counts labels (`predict`), soft averages `predict_proba`. If they disagree, look at how
  sure each member was (Labs 7, 11).
* **"Wrong by 0 / 1 / 2 / 3 members"** — a vote of three can only fix points wrong by **at most one** member. Many
  points wrong by two means the members' mistakes overlap and the vote will not help.
* **Correlation of mistakes** — near 0 (or negative) is good for voting; near 1 means the members are copies of each
  other as far as errors go.
* **Weights** — `weights=[1, 1, 3]` means the third member's vote counts three times. Only trust weights chosen by
  cross-validation on the training set.
* **Stacking coefficients** — the weight the final logistic regression gives to each member's probability; larger =
  trusted more.
* **Mean absolute error (regression)** — average distance between prediction and truth, in the target's units; lower
  is better.
* **Fit / predict times** (Lab 13) depend on your machine; compare the ratios, not the milliseconds.

If your numbers differ in the third decimal place from the saved outputs, that is due to library versions and is fine.
If a lab errors, re-run the imports cell and the cells above it — most errors mean a variable from an earlier cell is
missing.
